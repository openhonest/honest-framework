# honest-utilities Architecture

## 1. Purpose

honest-utilities holds a capability that several modules share and that belongs to none of them in particular. A capability moves here once at least two modules use it and no single module is its natural owner. The law runner, the environment-variable reader, and the recurring scheduler are the capabilities that live here now. honest-utilities sits in the foundation layer.

## 2. Shape

Every capability here is entered by import and runs from no flow of its own. honest-utilities never calls its sibling modules; the siblings reach into it. Each capability takes the framework's standard shape, so the crossing checker reads it with no exception: a door takes the import, hands its input to one orchestrator, and the orchestrator drives the pure functions that make the decisions and any reader that touches the world. The door and the reader are the only cards that touch the world or run code the module did not write; every decision behind them stays in a pure function, testable without the world. A capability whose boundary runs a caller's injected code is an engine; one whose boundary reads the world is a reader. A capability may be both, as the scheduler is: it runs the caller's injected work and reads the clock.

## 3. Composition

A caller states what it wants as data and hands that declaration in. honest-utilities owns the capability; the caller owns the declaration. A module declares a property and the law runner checks it; a module names the variables it needs and the reader reads them; a module hands the scheduler a unit of work and a cadence and the scheduler wakes it. Neither side reaches into the other's internals.

Each capability's functions and types are declared in honest-utilities.hd. The appendices below give the domain-specific contract the .hd is built from, one per capability.

## Appendix A — The Law Runner

A **law** pairs an identifier and a plain-language statement with a pure predicate. `law(identifier, statement, check)` returns a Law record of those three fields. The `check` is a pure function from one subject to a list of violation messages: it returns an empty list when the property holds for that subject, and one message per violation otherwise. A check never raises and never returns a bare boolean; the messages are the evidence a failure reports.

A **subject** is a `(name, params)` pair. The name labels the case for the report, and `params` is a record the check reads. One law is checked against many subjects, so the same property is proven across a bounded space of cases. A caller builds those subjects from the generators it already has: honest-test's Set enumeration (honest-test-architecture.md §3.2) and adversarial neighbors (§3.5).

`verify_laws(laws, subjects)` runs every law against every subject and returns a run record: how many law-and-subject pairs passed, the total checked, and a list of violations. Each violation names the law's identifier, its statement, the subject it failed on, and the messages the check returned.

Roles for the .hd: `verify_laws` is the door. It hands to the orchestrator `run_laws`, which drives a reader, `run_check`, and a pure function, `to_violation`. `run_check` runs one injected predicate against one subject's `params` and returns its messages; running the caller's predicate is the engine's boundary — honest-utilities executing code it did not write — so `run_check` is a reader whose world is `process`, not a pure function. `to_violation` records each failed pair as a Violation. `law` is the pure constructor a caller uses before anything enters.

Types: **Law** (`identifier`, `statement`, `check`), **Subject** (`name`, `params`), **LawRun** (`passed`, `total`, `violations`), **Violation** (`identifier`, `statement`, `subject` as the failing subject's name, `messages`).

## Appendix B — The Environment-Variable Reader

A module reads its configuration from the environment at startup: a database URL, a connection-pool size, a feature flag. Read by hand, each variable repeats the same three decisions in every module. Coerce the raw string to the type the module wants. Treat a missing variable as an explicit absence, never as a silent default. Fault on a value that is present but will not coerce.

A caller declares the variables it wants, each as a name, a target type, and whether it is required. `read_env(declarations)` reads the environment once and returns a resolved record: each present, valid variable coerced to its type; each absent optional variable set to `NOTHING`; and a fault when a required variable is missing or any value will not coerce. One fault names every variable at fault together, so a misconfigured deployment reports all its problems at once rather than one restart at a time.

A variable coerces to one of a closed set of target types: `str`, `int`, `bool`, `float`, `UUID`, or `key`. A `str` passes through. An `int` and a `float` parse as a number and fault on anything else. A `bool` reads `"true"`, `"1"`, `"yes"`, and `"on"` as true and `"false"`, `"0"`, `"no"`, and `"off"` as false, case-insensitive, and faults on any other word. A `UUID` parses as a UUID string. A `key` is a secret, such as an API key or token: it passes through as a string, but its value never appears in a fault message or anywhere else the module reports — only its name does.

Roles for the .hd: `read_env` is the door. It hands to the orchestrator `load_env`, which drives a reader, `read_raw_env`, and a pure function, `resolve_env`. `read_raw_env` pulls the raw strings for the declared names from the environment; reading the environment is the capability's boundary, so it is a reader whose world is `env`. `resolve_env` coerces each value, fills an absent optional variable with `NOTHING`, and collects the failures into one fault. It coerces by dispatching on the target type through `by_target_type`, which maps each of the six types to its own pure coercer: `coerce_str`, `coerce_int`, `coerce_bool`, `coerce_float`, `coerce_uuid`, and `coerce_key`.

Types: **EnvRequest** (`name`, `type_name` from the closed set above, `required`), **EnvValues** (each declared name mapped to its coerced value or `NOTHING`), and **Fault**. honest-utilities carries Fault as honest-type's shape across the seam — the four fields `code`, `message`, `category`, and `detail`, a bare union `X | Fault` recognized by shape with no ok/err envelope. A fault comes back on a missing required variable or a value that will not coerce.

## Appendix C — The Recurring Scheduler

A **schedule** wakes a unit of work on a cadence and runs until something stops it. A caller hands in the work, a cadence, a rule for what to do after each run, and a way to stop; the scheduler calls the work, waits the cadence, calls it again, and returns when the rule or the stop ends the loop. It decides nothing about the work: whether a refresh is due, what the work writes, and what a failure means are the caller's. The scheduler owns the waiting, the calling, the loop, and the retry count.

The **work** is an awaited callable returning `Done | Fault`; the scheduler runs it and reads back the result without looking inside, the same engine's boundary the law runner's `run_check` is. The **cadence** is a value the caller fills, never a vocabulary word: `interval_seconds` is the time from one run to the next, and `deadline_seconds` is an optional budget a run is expected to finish within. `plan_tick` computes the next due time as the last run plus the interval; it never matches a cadence name, so a caller with no fixed interval yet fills the number once it has one.

After each run the scheduler consults the caller's **decide**, a pure rule from the outcome and the run history to one disposition. decide reads the outcome (`Done | Fault`) and an Attempt context the scheduler holds — how many runs have faulted in a row, how many have run, and whether this run overran its deadline — and returns one of three dispositions the scheduler owns: **continue** runs again at the normal cadence, **retry_after** runs again after a delay decide computed from the fault and the count, and **stop** ends the loop. The scheduler owns the retry count as declared state, mutated only by `advance_schedule`, so a caller keeps no hidden counter of its own; the caller owns the reading of its faults, so the scheduler never interprets one. A spent retry budget is the caller seeing the fault count pass its ceiling and returning stop.

Two runs of one work never overlap. The loop waits for the in-flight run to return before starting another, even when the run passed `deadline_seconds` and the next due time is already past, so two runs can never rewrite one table at once. `deadline_seconds` is therefore an observation: the loop times each run between two clock reads, measures it against the deadline, and shows the result to decide for that same run as `attempt.overran`, never a release that abandons a run. The scheduler bounds every wait it owns — the cadence wait and the backoff wait are fixed numbers raced against the stop signal, and `plan_tick` never waits on a condition — so it cannot hang on its own waiting. The one wait it cannot bound is a caller's work that never returns, which the caller's work guards with its own query timeout so a stuck refresh returns a fault rather than never returning.

Stop is prompt and never cancels a running refresh. The idle wait is a race between the next due time and the caller's stop signal, so a stop ends an idle wait at once and never blocks shutdown; a run in flight at stop is left to finish, not killed, and the RunReport says whether one was. The scheduler reads the stop signal the caller flips; it installs no OS signal handler and never owns process exit. A loop ends for one of two reasons, both named in the EndReason vocabulary: the caller's decide returned stop, or the caller's stop signal fired.

The host owns the long-lived wait. One schedule is awaited for the life of the schedule, so a set of them is a set of awaited loops something must hold, and a module whose doors return cannot hold them without owning process lifetime. So honest-utilities offers two doors: **schedule** drives one unit of work, and **run_schedules** drives a set of ScheduleSpecs concurrently under one awaited call and one stop, which the host that owns the process awaits. A module declares its set of schedules and returns them; the host runs them. This is the shape honest-page's `create_app` takes, the host owning process lifetime.

Roles for the .hd: `schedule` and `run_schedules` are the doors, awaited, reached by import. `schedule` wraps its one unit of work in a ScheduleSpec under a fixed key and drives it; `run_schedules` hands each spec to a `drive_schedule` and awaits them together. `drive_schedule` is the orchestrator, awaited, the per-work loop. It reads the clock, calls the pure `plan_tick(state, now)` to choose wait, fire, or halt, and acts on the choice. On fire it brackets `run_work` with two clock reads to measure the run against `deadline_seconds` and set `overran`, calls the pure `build_attempt` to fold the outcome into the run counts, runs the caller's decide through `run_decide`, and folds the disposition into the next state with the pure `advance_schedule`; it repeats until `plan_tick` halts. The three pure functions hold every decision and read no world. `plan_tick(state, now) -> TickPlan` fires when `now` reaches the state's next-due time, halts when the state is stopping, and otherwise waits the gap; a fresh state has no next-due time, so the first run fires at once. `build_attempt(state, outcome, overran) -> Attempt` is the one place the retry count is folded: a fault raises `consecutive_faults`, a success resets it, and `attempted` counts every run. `advance_schedule(state, attempt, cadence, disposition, now) -> ScheduleState` carries the counts from the attempt and sets the next-due time from the disposition, `now` plus the cadence interval on continue and `now` plus the delay on retry_after, and marks the state stopping on stop; it is the single mutator of ScheduleState. `read_clock` is a reader whose world is the clock. `wait_until(seconds, stop) -> bool` is the bounded, stop-interruptible sleep, awaited, a reader whose world is the clock, returning whether the stop fired before the interval elapsed. `run_work` is the engine boundary, awaited, whose world is the process: it runs the caller's injected work and returns the opaque outcome, which the scheduler recognizes as honest-type's fault-or-not without reading the fault's kind. `run_decide` is the engine boundary that runs the caller's injected decide and returns a Disposition. `DispositionKind`, `TickPlanKind`, and `EndReason` are the closed vocabularies.

Types: **Cadence** (`interval_seconds: float`, `deadline_seconds: float | NOTHING`), **ScheduleSpec** (`key: str`, `work: Callable`, `cadence: Cadence`, `decide: Callable`), **ScheduleState** (`next_due: float | NOTHING`, `consecutive_faults: int`, `attempted: int`, `last_overran: bool`, `stopping: bool`) carried between turns and mutated only by `advance_schedule`, **Attempt** (`consecutive_faults: int`, `attempted: int`, `overran: bool`) the history decide reads, **TickPlan** (`kind: TickPlanKind` one of wait, fire, halt; `seconds: float | NOTHING` for wait; `reason: EndReason | NOTHING` for halt), **Disposition** (`kind: DispositionKind` one of continue, retry_after, stop; `delay: float | NOTHING` carrying retry_after's seconds), **RunReport** (`key: str`, `attempted: int`, `succeeded: int`, `faulted: int`, `overran: int`, `ended_reason: EndReason`, `in_flight_at_stop: bool`), and the vocabularies **DispositionKind** (continue, retry_after, stop), **TickPlanKind** (wait, fire, halt), and **EndReason** (decided_stop, signalled_stop). **Fault** is honest-type's shape carried across the seam, which the scheduler recognizes but never builds or inspects by kind.
